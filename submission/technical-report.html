Hybrid retrieval and source-backed answers on LoTTE Lifestyle

Technical report · 20 October 2026
Aryan Singh · Aryan Masrani · Chirag Jotwani

Abstract

The application exposes five retrieval choices: TF-IDF, BM25, Sentence Transformer, weighted two-way RRF and standard three-way RRF. The retained semantic method uses overlapping document chunks. RRF combines BM25 and semantic rankings with weights 1:4 and k=60. This configuration was retained by the user's choice of the stronger existing nDCG@10 version. Its saved test nDCG@10 is 0.615327, compared with 0.602541 for semantic retrieval. These descriptive results do not establish statistical significance or generated-answer accuracy.

1 Assignment and scope

The supplied assignment requests document chunking, tokenization, stemming, sparse and vector indexing, TF-IDF, BM25, Sentence Transformer, RRF context selection, LLM generation, a working search interface, performance tables and precision–recall graphs. The current scope is the Lifestyle domain, search queries only. The live app searches dev data. Standard RRF follows the PPT formula with equal contributions from TF-IDF, BM25 and original Sentence Transformer rankings. The existing weighted two-way RRF remains available and is the current default.

2 Preprocessing and retrieval

Lexical processing lowercases, tokenizes words and applies English stemming. Stopwords are retained. TF-IDF uses L2 normalization, sublinear term frequency and smoothed IDF, with a transposed CSR sparse postings matrix. BM25 uses the saved Lucene variant, k1=1.5 and b=0.75. Positive matches are sorted by score, with ascending passage ID for ties. Ranking does not consult relevance labels.

Sentence Transformer uses the saved intfloat/e5-small-v2 model, query/passage prefixes (query: and passage:), normalized 384-dimensional embeddings and exact FAISS inner-product search. Long documents use windows of up to 480 body tokens with 64-token overlap, checked against the 512-token input limit. Each original passage receives its maximum chunk similarity. Adaptive expansion returns 100 unique passage IDs. The dev index contains 295,689 vectors; embeddings of short passages were reused. No additional reranking model is used.

3 Standard and weighted RRF

For document d: score(d) = 1/(60 + BM25 rank(d)) + 4/(60 + semantic rank(d)). A missing component contributes zero. Fusion consumes the two top-100 lists and retains 100 results, breaking ties by passage ID. This version has higher nDCG@10 than the existing three-way weighted alternative on both saved splits; it is not best on every metric. The method and reported original scores were frozen before the original test evaluation. Test scores have since been inspected and cannot be reused to tune new settings.

Standard RRF sums 1/(60+rank) across the TF-IDF, BM25 and original semantic top-100 lists, without raw-score normalization. Missing components contribute zero; ties use passage ID. It uses the saved original semantic index and original passage context, while standalone Sentence Transformer and weighted RRF use chunks. Standard RRF has saved dev results only (nDCG@10 0.393792); no test score is inferred.

4 LLM and context selection

React/Vite calls FastAPI, which reads saved indexes and sends excerpts from the first three results to local Ollama qwen3:4b. Semantic matches use their best chunk when available. Each excerpt is limited to 550 UTF-8 bytes with sentence-aware clipping. Qwen produces structured evidence selections using temperature 0, a 4,096-token context and at most 768 output tokens. The server checks source IDs and exact quotation matches and expands partial selections to sentence boundaries. Invalid selections retry once; failures are explicit, and no-evidence selections abstain.

The LLM is active, but this is extractive selection rather than free-form synthesis. It is a narrower interpretation of the assignment's generation requirement. Exact quotations establish provenance, not source truth, relevance or completeness. Earlier prompting did not reliably prevent unsupported qualifiers; independent answer-quality evaluation is still needed before restoring synthesized prose.

5 Evaluation definitions

Binary relevance is macro-averaged over queries. P@10 divides relevant hits by ten. Recall@10 and Recall@100 divide by all labeled relevant passages. AP divides summed precision at relevant ranks by all labeled relevant passages; MAP averages AP. nDCG@10 uses binary gains and logarithmic discount with ideal ranking normalization. Success@5 is an additional diagnostic. Curves are 101-point interpolated precision–recall, truncated at 100 retrieved results. Missing positions are nonrelevant.

8 Attempts to improve existing methods

A new development-only experiment compared unchanged query processing against removal of common question words and English stopwords (keeping not/no/never). It reused the fixed passage indexes, stemming and ranking formulas. TF-IDF and BM25 were evaluated directly; BM25 variants were also fused with the unchanged semantic ranking. Candidate selection used 333 dev questions; the remaining 84 were used to report the selected candidate. For all three comparisons, the unchanged policy won on selection nDCG@10. No new policy was deployed and no benchmark scores were replaced. This previously inspected development split is exploratory, not an independent holdout. The report and exact results are in query-experiment-dev.md/json.

The retained semantic chunking is already an improvement attempt within the requested Sentence Transformer method. New chunk sizes or embedding changes would require separate indexing and independent validation; they were not claimed as improvements here. No test data was read for the new query experiment.
